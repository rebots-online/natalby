# Global rule: structured architecture representations

Scope: global; applies to every project, document, response and artifact that
presents or describes something as architecture.

Anything describing itself as architecture in any way MUST NOT consist only of
narrative or conversational language. It MUST include flows and a structured
depiction of the architecture: for example an AST, PlantUML (.puml), Mermaid
(.mmd), a graphical flowchart, or another explicit structural representation.
Prose may explain the representation but must not replace it.

Prefer a form that our BrAIInstormer project can directly recognize and represent
visually on its canvas, not only as a visual but as a functional program or program
fragment it can execute dynamically on the whiteboard canvas. This is a preference
for the representation, not authorization to invent a new format or to claim an
unverified format is supported or executable.

Operator wording, 27 October 2026:
> architecture content must always contain flows and depictions of the architecture
> in structured form, whether in AST puml mmd graphical raster image flowchart etc.,
> preferably in a form that our BrAIInstormer project can directly recognize and
> represent visually on its canvas not only as a visual but a functional program or
> program fragment it can execute dynamically on the whiteboard canvas.

> if a thing is describing itself as architecture in any way, it must not be only
> a narrative in conversational language.

The operator explicitly requested this be entered wholesale into global rules in
KStore Admin-Manual, without investigating BrAIInstormer as a diversion.
