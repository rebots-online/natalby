# Download access adapter — not yet deployed

The current frontend uses `VITE_DOWNLOAD_ACCESS_API_URL` only if explicitly configured. It is absent in the current deployment. The offer therefore reports purchasing unavailable. No live prepaid bypass or payment success has been demonstrated.

POST an HTTPS endpoint with Firebase Bearer ID token, JSON `{format,resourceId}`. The server validates the token, maps UID to the verified commerce customer, verifies actual entitlement/refund state, and binds access to the requested resource and format. Return JSON `{state:'owned',accountUid,resourceId,format,expiresAt}` only for actual prepaid access. For unpaid access return `{state:'offer',accountUid,resourceId,format,expiresAt,title,priceLabel,terms,checkoutUrl}` with an authoritative quote and HTTPS checkout session bound server-side to the same customer/purchase. No inferred membership, balance or payment-return flag may grant access. No client-provided price. Service must provide suitable CORS for the approved frontend, no-store responses, and a bounded expiry. Redirects are rejected by the client to avoid forwarding auth unexpectedly.

RevenueCat is the existing chosen adapter for PDF/SPA purchases (explicit Natally offering; preserve other ecosystem defaults), separate from ROCHE top-ups/Alby turns. Existing project source binding is LIBS/UI/OPENDESIGN/billing-preview-20261021/revenuecat-project.json. Product inclusions, WAV entitlement mapping, pricing, verified identity mapping, return/recovery, refunds and live webhook/API deployment are still pending actual commerce integration. No new endpoint, products, currency or grants were provisioned by this UI change.

The frontend rechecks on every app download request and after checkout when the user selects Check access; no durable frontend grant. Account changes invalidate pending operations and callbacks. The provider accepts no privileged keys. All delivered text/audio is already present for free exploration: the app download gate is not DRM. Strong protected artifact delivery would require server-controlled generation/storage and a separately approved change to this free experience.
